# BeThirty ZMK safe starter

これは、BeThirtyでZMKを試すための「最初の動作確認用」プロジェクトです。

安全側に倒すため、最初のキーマップには Home Row Mods を入れていません。
まずは「全キーが反応する」「ブートローダーへ戻れる」ことを確認するためのものです。

## 入っているもの

このプロジェクトは、O39Be / BeThirty Ortho系だけを対象にしています。

| シールド名 | 想定する本体 | キー数 |
|---|---|---:|
| `bethirty_ortho` | O39Be / BeThirty Ortho系 | 39 |

## 先にやること

Vialの現在レイアウトは保存済みとのことなので、次はこの順で確認してください。

1. Vial側で `QK_BOOT` をどこかに置く
2. `QK_BOOT` を押して、RP2040の書き込み用ドライブが出るか確認する
3. 何もコピーせず、USBを抜き差しして通常起動に戻ることを確認する
4. そのあとで、このZMKファームをビルドする

この確認をせずにZMKを書き込むと、戻し方が難しくなることがあります。

## ビルド方法

GitHubで新しいリポジトリを作り、この中身をそのままアップロードします。
`build.yaml` は `config` フォルダ内ではなく、リポジトリ直下に置いてください。
その後、GitHub Actions が走ると、UF2ファイルが生成されます。

リポジトリ直下の `build.yaml` では、次の1つだけをビルドする設定にしています。

```yaml
include:
  - board: rpi_pico
    shield: bethirty_ortho
```

生成された `bethirty_ortho` のUF2を使います。

## 書き込み方法

ブートローダーモードに入ると、パソコンにUSBメモリのようなドライブが出ます。
そのドライブへ、GitHub Actionsで作られた `.uf2` をコピーします。

コピーが終わると、自動で再起動します。

## この初期キーマップの考え方

通常レイヤーは、できるだけ普通のQWERTYにしています。

設定用レイヤーには、次を置いています。

| キー | 意味 |
|---|---|
| `&bootloader` | ファームを書き込めるモードへ入る |
| `&sys_reset` | いまのZMKを普通に再起動する |

`&bootloader` はとても大事です。
ZMKにした後は、Vialの `QK_BOOT` は使えません。

## Home Row Modsについて

このプロジェクトでは、最初はHome Row Modsを入れていません。
全キー確認が終わってから、`docs/hrm_next_step.md` を参考にして入れてください。

## 注意

このプロジェクトは、BeThirtyの公開QMK/Vial情報にある行列ピンと配列情報をもとに作った初期案です。
実機のリビジョン違いなどで、ピンや配列が違う可能性はあります。
最初に書き込む前に、実機の種類とUF2名が合っているかを必ず確認してください。
